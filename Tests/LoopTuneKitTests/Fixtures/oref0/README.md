# oref0 autotune golden parity fixtures

These fixtures were generated by running oref0's **real** autotune core
(`lib/autotune/index.js`, the `tuneAllTheThings` function) at oref0 commit
`88cf032aa74ff25f69464a7d9cd601ee3940c0b3` against small crafted
`preppedGlucose` inputs. The generator is
[`scripts/generate-oref0-fixtures.js`](../../../../scripts/generate-oref0-fixtures.js);
every expected value comes from that run.

## Oracle scope

The oracle covers selected ISF and basal tuning behavior on pre-categorized
data only. The inputs skip oref0's prep and categorization
(`lib/autotune-prep`), so the fixtures say nothing about LoopTune's replay,
deviation computation, or categorization. Every scenario has empty `CRData`
and `CSFGlucoseData`, so carb-ratio and CSF tuning are not exercised; the
unchanged `carb_ratio` is a NaN side effect (see below), not CR parity. Each
scenario is a single fresh day with one flat ISF and flat 1.0 U/h basals. Day
chaining, ISF schedules, DIA and peak tuning, and end-to-end recommendations
are outside the oracle.

## Regenerating

Requirements: Git, network access to GitHub, and Node.js 16 or later. The
autotune core loads only `lib/percentile.js`, so no `npm install` is needed.
Verified with Node.js 16.16.0, 18.13.0, and 26.3.0.

Clone the pinned revision into a disposable directory outside this repository
(not into `references/`, and never commit it):

```sh
OREF0_DIR="$(mktemp -d)/oref0"
git clone https://github.com/openaps/oref0.git "$OREF0_DIR"
git -C "$OREF0_DIR" checkout --detach 88cf032aa74ff25f69464a7d9cd601ee3940c0b3
```

From the repository root, verify the committed fixtures without writing:

```sh
TZ=UTC node scripts/generate-oref0-fixtures.js --oref0 "$OREF0_DIR" --check
```

Regenerate the fixtures in place, then confirm Git reports no change:

```sh
TZ=UTC node scripts/generate-oref0-fixtures.js --oref0 "$OREF0_DIR"
git diff --exit-code -- Tests/LoopTuneKitTests/Fixtures/oref0
```

Pass `--out <dir>` to write elsewhere, or with `--check` to compare against
another directory. The generator refuses a checkout at any other revision or
with modified tracked files. It also forces `TZ=UTC` before loading oref0 and
stops if local time is not UTC. Output is deterministic: repeated runs are
byte-identical. A difference from the committed fixtures means the inputs or
oracle changed. Investigate it instead of replacing the expected values.

## Fixture format

Each `<scenario>.json` contains:

- `input.isf` / `input.pumpISF` — starting sensitivity (mg/dL per U), 50.
- `input.carbRatio` / `input.pumpCarbRatio` — starting carb ratio, 10.
- `input.basalHourly` / `input.pumpBasalHourly` — 24 hourly rates (all 1.0).
- `input.prepped` — the exact `preppedGlucose` object passed to oref0
  (`CRData`, `CSFGlucoseData`, `ISFGlucoseData`, `basalGlucoseData`).
- `expected.sens` — `result.isfProfile.sensitivities[0].sensitivity`.
- `expected.carb_ratio` — `result.carb_ratio`.
- `expected.basalHourly` — 24 tuned rates from `result.basalprofile`.
- `expected.untuned` — per-hour `untuned` counter (0 when absent), i.e. the
  hours that were smoothed toward neighbors rather than tuned from data.

The run is a "fresh" autotune: `previousAutotune` and `pumpProfile` are
identical (deep copies), with sens 50, CR 10, CSF 5, DIA 6, curve
rapid-acting, autosens_max 1.2, autosens_min 0.7, min_5m_carbimpact 8,
timezone UTC. All glucose datums are on 2023-11-15 UTC (epoch-ms `date`
fields).

## Scenarios

- `isf_positive.json` — 20 ISF datums (glucose 150, BGI -4, deviations
  "0.80".."1.18" in 0.02 steps, avgDelta "-3.00"). Expected sens 48.333.
- `basal_positive.json` — 12 basal datums in hour 12 UTC (deviation "6.00",
  BGI -1). Expected hours 9-11 rise to 1.097.
- `mixed.json` — both of the above plus 2 negative basal datums in hour 3 UTC
  (deviation "-4.00"). Hours 0-2 drop to 0.99, hours 9-11 rise to 1.097,
  sens 48.333.

## Input-shape quirks discovered (must-match behaviors for a Swift port)

- **Strings vs numbers.** `categorize.js` stores `deviation` and `avgDelta`
  as strings via `toFixed(2)`; `BGI` is a number rounded to 2 decimals. The
  core does `parseFloat` on them. Fixtures preserve the string form.
- **Local time.** Basal deviations are bucketed by `new Date(date).getHours()`
  (local time). The generator sets `process.env.TZ = "UTC"` before requiring
  anything; a Swift port must bucket in the profile's timezone.
- **Mutation.** `tuneAllTheThings` mutates `previousAutotune` in place and
  returns it as the output object. The generator snapshots inputs first.
- **autosens caps come from `pumpProfile`** (`autosens_max`/`autosens_min`),
  not from `previousAutotune`; they default to 1.2/0.7 only when undefined.
  They are also only assigned inside the `if (pumpBasalProfile &&
  pumpBasalProfile[0])` block, so a pump profile without a basal profile
  would leave CSF/CR capping working on `undefined`.
- **Empty CRData produces NaN, leaving carb_ratio unchanged.**
  `totalCR = round(0/0*1000)/1000 = NaN`; `NaN !== 0` so `fullNewCR = NaN`;
  all NaN comparisons against the caps are false; `newCR = NaN` is falsy so
  `carbRatio` keeps its old value. Expected `carb_ratio` is therefore 10 in
  all three fixtures.
- **ISF path.** ratios are `1 + deviation/BGI` per datum; the p50 is taken
  with oref0's `lib/percentile.js` linear interpolation (`index = n*p`,
  `lower = floor(index)`, weight = fractional part; note index n*p, NOT the
  more common (n-1)*p). `p50ratios` is rounded to 3 decimals BEFORE
  `fullNewISF = ISF * p50ratios`, then `fullNewISF` is rounded to 3 decimals.
  With <10 ISF datums, ISF is left unchanged. `adjustedISF` (adjustmentFraction
  1.0 by default) is clamped to [pumpISF/autosens_max, pumpISF/autosens_min]
  BEFORE the 20% blend `newISF = 0.8*ISF + 0.2*adjustedISF`, and the blended
  result is clamped AGAIN to the same range, then rounded to 3 decimals.
  Example: p50ratio 0.755 -> fullNewISF 37.75 -> clamped to 41.667
  (50/1.2, unrounded in the clamp; 41.666…) -> newISF 48.333.
- **Basal path.** Per hour: sum that hour's deviations (round to 3 decimals),
  `basalNeeded = 0.2 * deviations / ISF` rounded to 2 decimals. If positive,
  add `basalNeeded/3` to each of the 3 prior hours (rounding each rate to 3
  decimals as you go). If negative, scale the 3 prior hours by
  `1 + basalNeeded/threeHourBasal` (using already-tuned running rates),
  rounding each to 3 decimals. Then clamp every hour to
  [pumpRate*autosens_min, pumpRate*autosens_max] and round to 3 decimals.
- **Untuned smoothing runs in a forward pass with a running state.** For each
  hour whose rate is still exactly equal to its pre-tune value, the new rate
  is `round((0.8*old + 0.1*newRate[lastAdjustedHour] + 0.1*newRate[nextAdjustedHour])*1000)/1000`,
  where `lastAdjustedHour` starts at 0 and only advances on hours that
  differed at check time, `nextAdjustedHour` is the next hour that currently
  differs (default 23), and — crucially — the referenced neighbor values are
  the LIVE, already-smoothed array (e.g. hour 1 reads hour 0's just-smoothed
  1.01, producing 1.011 instead of 1.01). The `untuned` counter is set even
  when the smoothed value equals the old value (see `isf_positive`, where all
  24 hours have `untuned: 1` yet rates stay 1.0).
- **DIA/peak.** With `curve: "rapid-acting"` and no `useCustomPeakTime`,
  peak is forced to 75 and DIA is unchanged (no `diaDeviations` /
  `peakDeviations` provided).
